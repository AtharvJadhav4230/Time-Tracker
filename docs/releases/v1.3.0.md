# Local Time Tracker v1.3.0

Export and back up your own local activity, inspect the previous week and run
without an installer using the new portable ZIP. Activity stays local by default.

## Desktop improvements

- CSV and JSON exports preserve Unicode and quoted window titles.
- SQLite backups include active WAL data and reject the source as destination.
- Previous 7 days complements Today and Last 7 days.
- Sampling and idle choices survive restarting the app.
- Ctrl+Tab/Ctrl+Shift+Tab and Alt+D/U/R switch the desktop tabs.
- Analysis failures clear stale information and recover when configuration is fixed.
- Recent activity preserves selection, focus and scrolling.
- Reports-folder and synthetic-data errors are handled clearly.

## Downloads

- `LocalTimeTracker-Setup-1.3.0-x64.exe`: Windows x64 installer.
- `LocalTimeTracker-1.3.0-portable-x64.zip`: extract into a writable folder;
  its `portable.mode` marker keeps data and preferences beside the executable.
- `SHA256SUMS.txt`: SHA-256 entries for both downloads.

Keep a backup of your activity before replacing an existing portable folder.
Keep the existing `data` directory if you want to retain history. Reset deletes
recorded activity only after confirmation; existing HTML reports remain.
No activity-database migration is introduced.

## Validation

The complete 67-test suite passes on Windows Python 3.11/3.13 and Ubuntu 3.12.
Five separate native Tk scenarios exercise real widgets, events, SQLite and
tracking/report threads with fictional activity. Dialog decisions and shell
opening are injected; this does not claim a human Windows 10/11 inspection.
Actual installer/portable builds are checked from the checkout and an outside
directory with spaces, including versions, ZIP contents and both hashes.

The portable executable is staged after application signing; CI without
signing credentials produces unsigned artifacts. See
[Windows validation](../WINDOWS_VALIDATION.md) for precise coverage.
